# Caffeine Build and Publish Runbook

Status: prepared for the project owner; no live deployment has been performed.

## Why this runbook exists

The GitHub branch `icpworld-onchain-upgrade` and the live Caffeine project at `https://icpmemeworld-65u.caffeine.xyz` have not been proven to be the same synchronized workspace. A GitHub commit does not update the live Caffeine app by itself.

Caffeine's current documented workflow is:
- Build and validate a local Caffeine workspace with the Caffeine CLI, or ask the hosted Caffeine builder to update the project.
- Use the Caffeine web app to publish/promote a draft to the live URL.
- There is no `caffeine deploy` or `caffeine publish` CLI command. `caffeine preview --build` uploads a draft; it does not publish it live.

References:
- Caffeine CLI and workspace workflow: https://skills.internetcomputer.org/skills/caffeine-app/
- Caffeine publishing and draft/live behavior: https://help.caffeine.ai/hc/en-us/articles/46899797134612-Publishing-and-Sharing-Your-App
- Caffeine stack and supported capabilities: https://help.caffeine.ai/hc/en-us/articles/46899843565972-What-Caffeine-Can-and-Cannot-Build

## Mandatory pre-publish checks

Do not promote a draft to live until all of these are true:

1. The Caffeine project opened in the owner's account is confirmed to be the intended ICPWorld Memepad project.
2. The draft is built from the intended source. Do not assume GitHub and Caffeine are synchronized; compare the source or explicitly import/apply the branch changes.
3. The Motoko backend build and stable-state check complete without errors.
4. Frontend typecheck, lint/check, and production build complete without errors.
5. Generated Candid and frontend actor bindings are regenerated by the Caffeine build. Do not hand-edit generated binding files as the production source of truth.
6. The preview is tested with a non-admin user and the founder's actual Internet Identity principal.
7. The live backend's access-control initialization, first authenticated user, CEO/admin state, and canister controllers are inspected before any upgrade. Caffeine's authorization mixin bootstraps the first authenticated user as admin, while this project also has a custom first-caller CEO initializer. Do not assume the first user was the owner; verify the live state and founder principal before any change.
8. The preview clearly marks deposits, withdrawals, token launches, and swaps as unavailable until each real integration is implemented and tested.
9. No test uses real funds. Mainnet ledger transfers, token deployment, and DEX swaps are out of scope for a UI-only publish.
10. The owner reviews the final preview and explicitly chooses Publish/Promote in Caffeine.

## Current safety state of the GitHub branch

The development branch contains:
- A read-only ICP Ledger balance query for the principal-derived subaccount.
- A portfolio display that separates the real ledger balance from legacy app accounting.
- Backend safety guards that reject legacy simulated withdrawals, token launches, and trades.
- An explicit false/disconnected ICPSwap status until a real integration exists.

This branch is not yet build-verified. The repository's `deploy.sh` starts a local ICP network and deploys to that local environment; it is not a Caffeine mainnet publishing script.

## Prompt for Caffeine's hosted builder

Open the existing ICPWorld Memepad project in the Caffeine web app and send the following as one instruction. Do not create a new project unless the existing project cannot be opened.

---

You are updating my existing ICPWorld Memepad project, not creating a replacement. Preserve the current project identity, design, routes, user data, stable state, and all working features.

First inspect the complete current project and report the actual backend/frontend architecture, canister state, authentication/admin initialization, all wallet/deposit/withdrawal/token-launch/trading/swap code paths, and all hardcoded or simulated market data. Do not make changes until you have reported the findings and a build plan.

Apply the safety requirements below:
- A displayed verified ICP balance must come from the ICP Ledger for the authenticated user's exact account/subaccount. Keep legacy app accounting visibly separate and never imply it is spendable.
- The current principal-derived deposit account is user-controlled. Do not represent it as a canister escrow account. Do not tell users to deposit until deposit discovery and idempotent reconciliation are implemented and verified.
- Do not report a withdrawal as completed unless a real ICP Ledger transfer succeeds and its result is reconciled. Require explicit wallet signing/approval for user-originated transfers.
- Do not claim a memecoin is launched on-chain unless an actual ICRC ledger canister is created, token metadata and controller policy are verified, and the token ledger ID is displayed from the real deployment result.
- Do not claim a swap or liquidity action succeeded unless a supported DEX transaction is actually submitted, confirmed, and linked to its real transaction/block reference.
- Remove or disable all fake swap completion, fake transaction history, synthetic prices/volume/market-cap/holder statistics, fabricated token addresses, and fake launch success screens. Label unsupported features as "Not yet enabled" rather than simulating success.
- Never assign CEO/admin to the first visitor. Preserve and verify the founder's existing authorized principal; if that principal cannot be established safely, stop and request owner action rather than changing admin state.
- Do not change production controllers, move funds, deploy tokens, or execute mainnet transactions.
- Regenerate Candid and frontend bindings through the supported Caffeine build workflow. Never hand-edit generated bindings.
- Run backend stable-state checks, backend build, frontend typecheck, frontend lint/check, and frontend production build. Fix all errors and show the actual outputs.
- Provide a preview for owner testing. Do not publish/promote it live until the owner has reviewed the preview and explicitly clicks Publish.

The first delivery is a truthful, safe app with real read-only ledger balance visibility and honest disabled states. Real deposit reconciliation, wallet-approved withdrawals, ICRC token creation, and DEX trading are separate later milestones and must not be represented as complete until each is independently implemented and tested.

---

## Owner publishing steps

1. Open the existing project at https://caffeine.ai while signed into the account that owns ICPWorld Memepad.
2. Open the existing ICPWorld Memepad project. Verify the project name and current live URL before sending the builder prompt.
3. Review the builder's inspection report and proposed changes. Confirm it is modifying the existing project, not a new blank project.
4. Let Caffeine build a draft/preview. Require visible backend and frontend build results.
5. Test login, portfolio balance display, and all disabled states in the preview. Do not send ICP to the legacy deposit address.
6. Only after the checks above pass, use Caffeine's Publish/Promote control to update the live app.
7. Open the live URL in a private/incognito tab and verify the published version. Record the release date and build details.
